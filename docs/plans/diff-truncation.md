# 规格：diff 截断（PR A）

> 状态：已实现（见 decisions.md D018）。PLAN §三 关键工程细节的最后一项未落代码项；验收标准 #4 要求 README「讲清」它，先实现再讲。

## 背景

`reviewDiff` 目前把整个 diff 全量喂给模型。超大 PR（journal 会话 9：PR #1 diff 37KB 大半是 package-lock 噪声）一是浪费 token，二是可能超模型上下文窗口直接失败。PLAN §三 预留的截断策略未实现。

## 方案

**整文件块预算丢弃**（不切 hunk、不分子调用）：

- 以 `diff --git ` 行为界把 diff 切成文件块；总长 ≤ 预算原样返回。
- 超预算：按块大小升序贪心保留（小文件优先——大文件多为 lock/生成物，正是 PR #1 印证的噪声），装不下的跳过、继续尝试更小的；保留块按原顺序重组，字节级保真。
- 被丢弃的文件在 diff 末尾逐个附一行 `[diff 截断] 省略 path (+a/-b)`，让模型知道审到的不是全量。
- 预算 `DIFF_MAX_CHARS` 字符数，默认 300_000（≈ 模型上下文的安全余量），非法值告警回退默认（与 `LLM_TIMEOUT_MS` 同款）。
- 落点：`src/review.ts` `truncateDiff()`，`reviewDiff` 构造 prompt 前应用——LLM 输入预算是模型层约束，单一切入点 webhook / eval / 本地脚本自动全部生效。
- `diffCoveredLines` 仍吃原始 diff：被截断文件模型看不到、不会有意见，覆盖行号是其超集，无害。

## 备选（放弃理由）

- **按行数截断单文件**：破坏 hunk 完整性 → `diffCoveredLines` 行号错位、模型理解断片。
- **按文件分批多次调用 LLM**：多次调用成本与延迟翻倍，意见间互相看不到上下文；一期不做（v2 若超大 PR 常见再上）。
- **内容级过滤（lock 文件黑名单）**：机械预算已天然把大噪声文件排后面，黑名单是第二套规则没有第二份收益。

## 验收

- 单测：预算内原样返回 / 超预算丢最大块、保序重组 / 省略行含路径与增删计数 / 全部放不下返回纯省略列表 / env 非法回退。
- `tsc --noEmit`、`npm test`、`npm run eval` 回归通过。
